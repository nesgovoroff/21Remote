# 21 Remote — передача дел

Состояние на 21 ноября 2026. Что пользователю — в [README.md](README.md); здесь то, что нужно знать, чтобы
продолжить работу над кодом.

## Что это

Программа для macOS, управляющая стойкой D21m (карты Mic, DL5, GPIO, AES/EBU, ADAT; усиление, 48 V, фильтры,
имена, сессии) через последовательный порт (USB-адаптер RS-422) или преобразователь RS-422 ↔ Ethernet
(TCP Server / TCP Client). Плюс MIDI (виртуальный порт с фиксированной картой и MIDI Learn), плагины для DAW
(AU, VST3, JS для REAPER), обновления из релизов GitHub, установщик .pkg. Свободная программа, AGPL-3.0-or-later.

* Репозиторий: **github.com/nesgovoroff/21Remote** (публичный; раньше назывался D21m-remote-mac, GitHub
  перенаправляет старый адрес).
* Ветки:
  * `main` — macOS 11+, universal (Apple Silicon + Intel). Релиз **v1.1.3** (`21-Remote-1.1.3.pkg`), помечен
    latest.
  * `old_macos` — OS X 10.10 – macOS 10.15, только Intel. Релиз **v1.1.3-macos10**
    (`21-Remote-1.1.3-macOS10.pkg`), никогда не помечается latest.
* История `main` схлопнута в один коммит «21 Remote 1.1.3» (по просьбе владельца, чтобы не осталось старого
  названия); поверх — правки README от владельца и этот файл.

## Устройство

| Часть | Где | Коротко |
|---|---|---|
| Движок | `cmd/remote21-core`, `internal/*` | Go без cgo. Опрос стойки, очередь команд, модель карт, сессии, отмена, MIDI-логика, API плагинов, локальный веб-сервер 127.0.0.1 (вход по одноразовому токену, cookie `r21`, обновления по SSE). |
| Протокол стойки | `internal/proto` | 115200 8N1, кадр `[0x80\|адрес][данные][контрольная сумма]`. Тест-сервер: `tools/fakeserver` (TCP, имитирует стойку). |
| Порты | `internal/serial`, `internal/netport` | Последовательный порт (darwin/linux) и TCP к преобразователю. |
| Оболочка | `macos/shell.c` | C через Objective-C runtime без Xcode: WKWebView, меню (сессии, Open Recent, Window → Scale 50–125 %), значок в строке меню, запуск движка, фоновый старт от плагинов. |
| MIDI | `macos/midi.c`, `internal/midi`, `internal/core/midiengine.go` | Мост CoreMIDI ↔ движок через файловые дескрипторы; парсер с SysEx. Карта CC: MIDI-канал = слот, CC 127 = запрос всех значений слота. |
| Интерфейс | `web/` | HTML/CSS/JS без сборщика, встроен в движок. |
| Плагины AU/VST3 | `plugins/channel`, `plugins/overview`, `plugins/common` | JUCE 8.0.4 (AGPL), коды производителя `Rm21`, плагинов `R21c` / `R21o`. Связь с программой по TCP: порт 47210, файл `plugin.json` в папке настроек. |
| JS-плагины | `plugins/jsfx` | `21 Channel.jsfx`, `21 Overview.jsfx`, общий `remote21.jsfx-inc` (gmem `Remote21`), Lua-мост `21 Remote Bridge.lua`, обменивающийся файлами с движком в `<настройки>/bridge` (`client.beat`, `state.txt` с заголовком `R21 1`, `commands.txt`). Код движка — `internal/core/bridge.go`. |
| Обновления | `internal/update` | Проверка релизов GitHub, токен необязателен (нужен только для приватного репозитория, хранится в связке ключей), установка .pkg через `osascript … with administrator privileges`, перезапуск. |
| Установщик | `macos/pkg.sh` | Компоненты: app, AU, VST3, JSFX (+ строка в REAPER `__startup.lua`). |
| Картинки | `tools/art/cards.py` | Рисует все `web/img/*.png` с нуля (Pillow, шрифты DejaVu). |

Настройки: `~/Library/Application Support/21 Remote/` (settings.xml, midi.json, bridge/, plugin.json).
Журнал: `~/Library/Logs/21 Remote.log`.

## Сборка и релизы

* Тесты: `go test ./...`. Приложение: `./macos/build.sh` — собирается и на Linux (clang + ld64.lld + заглушки
  `macos/tbd/*.tbd`), на macOS дополнительно подписывается ad-hoc. Плагины и .pkg — только на macOS (в CI).
* Версия — в `VERSION`, описание релиза — в `notes/<версия>.md`. CI (`.github/workflows/build.yml`) собирает на
  каждый push и публикует релиз, если релиза для этой версии ещё нет. Чтобы выпустить версию: поднять `VERSION`,
  написать `notes/<версия>.md`, закоммитить, запушить.
* `maintenance.yml` (запуск вручную, в т.ч. через REST `workflow_dispatch`): удалить релизы с тегами, перенести
  тег, перезагрузить описание релиза. Нужен потому, что из сессии Claude нельзя править релизы и настройки
  репозитория напрямую.
* Подписи разработчика и нотаризации нет (решение владельца): при установке macOS просит «Open Anyway».

### Ветка old_macos

* Движок собирается **Go 1.12** (последний Go для 10.10): никаких generics, `any`, `embed`, `errors.Is/As`, `%w`,
  `os.ReadFile`, литералов `0o…` и т. п. Замены — в `internal/compat`. Код должен проходить тесты и на Go 1.12,
  и на новом Go.
* Интерфейс не встраивается через `embed`: `macos/legacyweb.py` при сборке генерирует `web/assets_gen.go` (в
  .gitignore), переводит `app.js` в ES2016 (esbuild), добавляет `web/legacy/polyfills.js` (`<dialog>`, pointer
  events, проверка flex gap) и правит CSS (`gap` → `grid-gap` и отступы под `html.nogap`, `inset`, префиксы).
* CI: приложение собирается на ubuntu (setup-go 1.12.17; Go 1.12 нет для Apple Silicon), плагины и .pkg — на
  macos-14. Плагины AU/VST3 — для macOS 10.13+ (старше нынешний Xcode не собирает); установщик на 10.10–10.12
  их не показывает.
* Обновления в этой ветке берут только релизы `v<версия>-macos10` из списка релизов; `main` смотрит только
  `releases/latest`, поэтому ветки друг другу не мешают.
* Изменения из `main` в `old_macos` переносятся вручную (cherry-pick с адаптацией под Go 1.12 и старый WebKit).

## Чего здесь нет и что важно знать

* Проверить на настоящей стойке и на старых macOS может только владелец: в окружении только имитатор
  (`tools/fakeserver`, режим DEMO в программе).
* Если «стойка не отвечает», а соединение есть — программа пишет об этом под стойкой (первым делом проверить,
  включена ли стойка; так уже было).
* Ограничения окружения сессии: прямые загрузки с dl.google.com и реестров пакетов могут быть закрыты (Go 1.12
  собирался из исходников с github.com/golang/go; esbuild лежит в `/opt/npm-tools`); логи GitHub Actions не
  скачиваются — ошибки шагов CI выводятся аннотациями через `.github/step.sh`.
